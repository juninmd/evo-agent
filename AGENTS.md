# AGENTS.md

Workspace instructions for `evo-agent`.

## Persona

- Operate as Super Expert: SecOps > QA > DevOps > SWE.
- Prefer evidence, small diffs, and reproducible checks.
- Keep prose compressed and technical.
- Protect secrets. Never print tokens, credentials, or private env values.

## Project

`evo-agent` is a TypeScript self-improving AI publishing agent.

Core flow:

1. Crawl AI/developer sources into SQLite.
2. Improve agent state from recent sources.
3. Generate pt-BR articles and weekly reports.
4. Publish Markdown and Jekyll assets to GitHub Pages.
5. Notify Telegram after successful publishing.

## Development Rules

- Read before write.
- Keep changes surgical.
- Do not refactor adjacent code unless required.
- Use `npm run build` and `npm run lint` before calling work done.
- For Reddit community signals, use `npm run smoke:reddit-comments` with isolated DB before enabling production flow.
- Do not commit generated SQLite databases, WAL/SHM files, local reports, or secrets.

## Publishing Rules

- GitHub Pages content is generated by `src/publisher/github.ts`.
- The Pages UI must preserve:
  - light/dark theme toggle
  - article archive by year/month
  - dark-readable and light-readable article content
  - Markdown download button
  - corrected header anchors for `Arquivo` and `Relatorios`
  - canonical URL, Open Graph/Twitter metadata, Atom feed and sitemap
  - skip link and an `aria-pressed` theme toggle
  - "Nesta edição" table of contents and the primary-source/community-signal markers
- Both layouts are generated from the shared builders in `site-renderer.ts`; do not fork them. CSS lives in `src/publisher/styles/`; bump the `site.css?v=` query when it changes.
- Every `{{ page.* }}` interpolation must carry `| escape`: Liquid does not escape by default and titles come from crawled text.
- Published articles may include images/videos when they improve validation or reader understanding.

## Security

- Keep `.env` local.
- Rotate any token that returns `401 Bad credentials`.
- Use GitHub app/connector or a valid token for Pages publishing.
- Community comments are signals, not authoritative sources.

## Console rules

- Every `/api/v1` payload is camelCase, including SQL aliases, because the Rust structs in
  `desktop/src-tauri/src/types.rs` mirror the keys field by field. A `snake_case` key that
  escapes is a runtime break, not a compile error.
- A Rust command name must equal its `invoke` name in `desktop/src/lib/api.ts`; the vitest
  suite in `src/lib/api.test.ts` pins both sides.
- The API is read-only: `POST /api/v1/runs` executes a child process instead of running the
  cycle in the API process. `API_ALLOW_RUNS` defaults to false.
- The `API_TOKEN` lives in the Rust process and in `settings.json` in the app config dir. It
  must never cross the IPC: `settings_get` answers `hasToken`, never the value.
- Run `cargo test --test live_api -- --ignored` against a live agent after changing the API
  contract: it is the only test that compares the structs with the JSON Node really returns.
- A UI change goes through `npm run e2e` and ships the regenerated screenshots in
  `docs/prints/` in the same PR. The specs are the only place that renders the interface, so a
  component that nothing asserts and that no screenshot shows is unverified.
- Tab labels are pt-BR and so are the labels derived from API enums (`runModeLabel`,
  `healthReasonLabel`). Raw contract values (English health reasons, SQL slugs) are translated
  at the edge, in `src/lib/i18n.ts`, never printed as they arrive.
