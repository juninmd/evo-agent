### Kubernetes v1.37: KubeletInUserNamespace (Rootless mode) Graduates to Beta
**O que mudou:** O recurso KubeletInUserNamespace foi promovido para beta no Kubernetes v1.37, permitindo que kubelet, CRI, OCI runtimes, CNI plugins e kube-proxy executem como usuário não-root no host usando namespaces de usuário Linux.
**Por que importa:** Seu time usa k3s (baseado em Kubernetes) e Argo CD. Essa mudança permite executar clusters com menor superfície de ataque, essencial para ambientes de produção seguros. Requer atualização de k3s e verificação de compatibilidade com Traefik e outros componentes que rodam no nó.
**Acao:** testar
**Fonte:** https://kubernetes.io/blog/2026/09/04/kubernetes-v1-37-rootless-beta/

### Hono v4.13.7: Security fix for XSS in JSX rendering
**O que mudou:** Foi corrigida uma vulnerabilidade de XSS em hono/jsx onde strings simples eram renderizadas sem escape em componentes de limite (Suspense, ErrorBoundary, Context.Provider), afetando também renderToString() e renderToReadableStream().
**Por que importa:** Seu stack usa Hono no frontend/backend. Essa falha poderia permitir injeção de script malicioso se dados não confiáveis fossem renderizados em componentes JSX. Correção crítica para segurança de aplicações.
**Acao:** testar
**Fonte:** https://github.com/honojs/hono/releases/tag/v4.13.7

### LiteLLM v1.103.0-dev.2: Docker image signature verification with cosign
**O que mudou:** Todas as imagens Docker do LiteLLM agora são assinadas com cosign usando uma chave fixa (commit 0112e53). Recomenda-se verificar usando o hash do commit para garantir integridade.
**Por que importa:** Você usa LiteLLM para gerenciar modelos de IA. Garantir que as imagens não sejam adulteradas é essencial para segurança da cadeia de suprimentos, especialmente em ambientes de produção com k3s e Argo CD.
**Acao:** testar
**Fonte:** https://github.com/BerriAI/litellm/releases/tag/v1.103.0-dev.2

### Traefik v2.11.57: Multiple CVEs fixed and recursive NSS propagation disabled by default
**O que mudou:** Foram corrigidas CVEs (GHSA-qqjf-53cj-pwvv, GHSA-f52w-8j3h-j724, GHSA-w4v4-9rw7-5326) e o recurso de propagação recursiva de NSS para desafios DNS do ACME foi desativado por padrão.
**Por que importa:** Você usa Traefik como ingresso no cluster k3s. Essas correções de segurança são críticas para evitar vulnerabilidades em exposição externa. A mudança no comportamento do ACME pode afetar renovação de certificados se não for revisada.
**Acao:** testar
**Fonte:** https://github.com/traefik/traefik/releases/tag/v2.11.57
